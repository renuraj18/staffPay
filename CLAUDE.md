# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install
npm start                              # http://127.0.0.1:8000 (override with PORT)
npm run dev                            # node --watch auto-restart
npm test                               # node:test over tests/*.test.js
node --test --test-name-pattern="late" tests/payroll.test.js   # single test
```

No lint or bundler; the frontend is plain HTML/CSS/JS served from `public/`. `npm run build:exe` packages the server + `public/` with Node 22 into `dist/StaffPay.exe` using `@yao-pkg/pkg` (works from macOS too; test a packaged build locally with `npx pkg . --targets node22-macos-x64` (or `-arm64` on Apple Silicon) and run it with `--no-open`).

## Windows distribution & releases
- Packaged runs (`process.pkg` set) store data in `%LOCALAPPDATA%\StaffPay\data` by default (the Folders page can move it; `STAFFPAY_DATA_DIR` overrides and locks it), open the browser on start (`--no-open` disables), and if the port is already serving StaffPay they just open the browser and exit.
- `installer/StaffPay.iss` (Inno Setup, per-user, no admin) installs to `%LOCALAPPDATA%\Programs\StaffPay` with Start menu + desktop shortcuts. Asset names are fixed (`StaffPay-Setup.exe`, `StaffPay-Portable.zip`) so `releases/latest/download/…` links always work — don't add versions to them.
- `.github/workflows/release.yml` runs on `v*` tags (tag must equal `package.json` version): tests, build exe, installer, portable zip, GitHub release. `ci.yml` runs tests on pushes/PRs. To release: on `main`, `npm version patch|minor|major` (bumps version + creates the tag), then `git push --follow-tags`.
- `lib/update.js` + `GET /api/version` (`?force=1` skips the 30-min cache) compare `package.json` version with the latest GitHub release of the repo in `package.json` `repository`. **Self-update** only in the installed Windows app (`canSelfUpdate`: packaged, win32, `unins000.exe` next to the exe; portable/source copies get a download link): `server.js` checks 15 s after start and every 5 min (GitHub hit at most every 30 min); with `config.auto_update` (default on) a new release's `StaffPay-Setup.exe` is downloaded to `%TEMP%` right away and installed once no `/api` request (other than `/api/version`/`/api/update` polls) has come for 5 min; `POST /api/update` ("Update now") installs at once. Installing = backup, then `runInstaller` writes `%TEMP%\StaffPay-update.cmd` (wait → setup `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS` → start the exe with `--no-open`), spawns it detached and exits; the page polls `/api/update` and reloads when `/api/version` reports a new version. Auto-update only works from a version that has this code — older installs need one manual install. Check failures are silent.
- `data/` is gitignored (real staff data) — never commit it.

## Architecture

Single flow: upload biometric report (Excel or PDF) → parse → calculate salary → view/adjust → export Excel.

- `lib/payroll.js` — pure functions, no I/O. `parseWorkbook(buffer)` turns each worksheet into rows and hands them to `parseSheets(sheets)`, which reads the "Daily Details Report" format: one sheet per employee, `Employee Name : X , Employee ID : N` header line, `Company :` and `From … To …` lines, then a table with `Date / Check In / Check Out / Clock In / Clock Out / Total WT / Status`. **Check In/Out are the shift schedule; Clock In/Out are the actual punches** — only Clock columns are used. Text dates are DD-MM-YYYY. `LE` (Leave, PDF report) is absent without punches, a workday with them. `classifyDay(day, rules, shift)` maps the bracketed status code (`P`, `LT`, `EL`, `HD`, `A`, `WO`, `WOP`, `H`) via `STATUS_KIND`; late and missing punch are computed from punch times against the employee's **shift**, not taken from the device status. **Early leave is not marked at all** (user request; the device's `EL` is treated as a normal workday). Unknown codes fall back to punches and produce a warning. `calculatePayroll(parsed, settings)` produces per-employee totals and the full day list. `normalizeSettings` fills defaults and migrates older formats; it is gated on `settings.version` (`SETTINGS_VERSION` = 4): daily→monthly salary conversion (× divisor) runs only for version < 2, the version-3 rule reset (`allowed_absences` 0, `sunday_logout_time` 15:00) only for version < 3, and the version-4 overtime reset (`V4_OVERTIME`: min 60, block 30 — defaults and every company's own rules) only for version < 4 — bump the version for any future migration.
- `lib/pdf.js` — `pdfToSheets(buffer)` (async, `pdf2json`) for the "Daily Attendance Report (Detailed Report)" PDF: one employee per page, text drawn glyph by glyph. Glyphs are grouped into lines (y) and cells (x gaps), each cell goes to the horizontally nearest header column, and the result is fed to `parseSheets` in Excel column order (`Actual WT` → `Total WT`; period line has no `From`). A page without an `Employee Name` line continues the previous employee. The input buffer is copied first — pdf.js ignores Buffer offsets, so pooled (small) buffers parse as garbage. pdf2json logs a harmless "Setting up fake worker" warning per upload.
- `lib/export.js` — builds the output workbook (Salary Summary, Daily Attendance, Advances when any, Assumptions) (`monthLabel` for "September 2026").
- `lib/slip.js` — one-page A4 PDF slip per employee (`pdf-lib`, built-in Helvetica so no font files to package — amounts are "Rs." because standard fonts lack ₹; Indian digit grouping is done by hand since packaged Node may lack Intl data): header, attendance tiles, salary breakdown, net payable, advance summary + details, attendance calendar. `buildSlipsZip` zips all slips (`fflate`) as `<Name> - <Month YYYY>.pdf` (duplicate names get ` (id)`). The slip header shows the employee's company (falls back to the sheet's company).
- `server.js` — Express, binds to 127.0.0.1 only (optional PIN, see below). Stores every uploaded month in `data/months/YYYY-MM.json` (`lib/store.js`) and settings in `data/settings.json` as `{version, rules, shifts: [{id, name, login_time, logout_time, grace_minutes}], staff: {empId: {name, shift_id, salary, company_id, bank_account_name, bank_account_number, bank_ifsc}}, companies: {id: {name, bank_name, account_name, account_number, ifsc, rules?}}, advances: {id: {emp_id, date, amount, installment, start_month, note, overrides: {'YYYY-MM': amount}}}}` (salary is monthly). The report is **recalculated on every request** from settings + the open month (`monthReport`), so settings changes apply retroactively to unlocked months; a **locked** month returns its frozen `locked.report` (paid status still applied via `applyPaid`). `loadSettings()` always merges employees from the open month into `staff`. **Staff identity**: device employee IDs repeat across devices/reports (another firm's report can have a different person as ID 2), so on upload `resolveStaffIds` matches each sheet employee to a staff record by ID *and* name (`nameKey`: case/punctuation/word order ignored); a different name gets a new key `<id>_2` with `device_id` and an upload warning. `parsed.employees[].id` is stored already resolved (the staff key used by advances, companies, bank details); UIs and exports show `device_id`. `PUT /api/settings` takes a patch: `rules` (partial), `shifts` (full replacement; staff in removed shifts move to the first), `companies` (per-id partial, `null` removes and unassigns its staff; `rules`: partial patch of the company's own rules, `true` starts them as a copy of the defaults, `null` = use the defaults; validated by `applyRules` like `body.rules`; applied before `staff` so one patch can create and assign), `staff` (per-id partial, `null` removes; bank fields validated — IFSC upper-cased, account number spaces stripped, `''` clears), `advances` (per-id partial, `null` removes; `overrides` merge per month, `null` clears). State responses are `{settings, report, month, advances}` — `advances` is computed for the sheet's month (or the current month with no upload). Endpoints: `POST /api/upload`, `GET /api/state`, `PUT /api/settings`, `GET /api/export.xlsx`, `GET /api/companies/:id/bank-transfer.xlsx` (`buildBankTransfer`: Transfers sheet for the bank's bulk upload — every employee of that company in the current sheet with net salary as the amount, bank fields from Staff left blank when missing, paid from the company's account, IFT when IFSC bank code matches the company's else NEFT; Summary with total and missing-bank count), `GET /api/staff/:id/slip.pdf`, `GET /api/slips.zip` (`Salary slips - <Month YYYY>.zip`), `POST /api/slips/save`, `GET|PUT /api/folders`, `POST /api/backup`, `GET /api/version`, `PUT /api/app`, `GET|POST /api/update`.
- `lib/folders.js` + Settings page — the data folder and the output folder (payslips; default `~/Documents/StaffPay`) are kept in `config.json` *outside* the data folder (`%LOCALAPPDATA%\StaffPay\config.json` packaged, `data/config.json` from source) as `{data_dir, output_dir, backup_dir, auto_update}` (absent = default; `PUT /api/app {auto_update}`). `PUT /api/folders` changes them: a new data folder without StaffPay files gets a copy of `settings.json` + `current_upload.json`, one with them is used as is; the old folder is never deleted. `POST /api/slips/save` writes every slip to `monthDir(output, month)` = `<output>/<YYYY>/<MM - Month>/` (same names replaced) and the UI opens that folder. `POST /api/folders/pick` shows a native folder dialog (PowerShell `FolderBrowserDialog` on Windows, `osascript` on macOS); `POST /api/folders/open` opens only `data`/`output`/`month`/`backup`, never an arbitrary path.
- `lib/backup.js` — `createBackup` writes `<backup_dir>/StaffPay backup YYYY-MM-DD HHMMSS[ (reason)].zip` (default `~/Documents/StaffPay/Backups`) with `config.json`, `data/settings.json`, `data/current_upload.json`, `backup.json`. `POST /api/backup` = Back up now; automatic backups before installing an update and before changing the data folder (`backupQuietly`, never blocks). No restore UI yet.
- `public/app.js` — sidebar with eight pages (Salary, Salary rules, Staff, Companies, Shifts, Advances, Reports, Settings; page kept in the URL hash). `showRules(scope)` opens the Salary rules page for a company (from the Salary page button and company cards). Every edit `PUT`s a settings patch and re-renders from the returned `{settings, report}`; `renderAll` restores focus via `data-key` attributes. **Shift cards are edited as local drafts and saved only with their Save button/Enter — never re-render a shift card's inputs while typing** (Chrome time inputs lose their hour/minute segment position and produce wrong times).

## Months, corrections, payments (v1.2)
- **Month history** (`lib/store.js`): `data/months/YYYY-MM.json` = `{month, file, uploaded_at, parsed, edits: {days, adjustments, paid}, locked: null | {at, report}}`; `data/meta.json` `{active_month}` (default newest). `migrateData()` at startup moves a legacy `data/current_upload.json` into months/ (kept as `.migrated`) and applies the v5 ID renames to every month. Upload of a month that exists → 409 `{code:'exists'}` unless `?replace=1` (edits kept); locked month → 409 `{code:'locked'}`. Upload responses add `upload_summary` (new staff, renamed duplicate IDs, left staff, no salary/company/bank, warnings). Endpoints: `PUT /api/months/active {month}`, `DELETE /api/months/:m` (not when locked), `POST /api/months/:m/lock {locked}` (lock stores `calculatePayroll` output as the frozen report), `PUT /api/month/edits` (open month: `days {emp:{date:{status,note}|null}}`, `adjustments {emp:{id:{kind,label,amount}|null}}`, `paid {emp:{date,note}|null}`; locked months accept only `paid`). State responses add `months`, `active_month`, `undo`.
- **Corrections / adjustments** (`calculatePayroll(parsed, settings, edits)`): `correctDay` overrides a classified day (`DAY_FIXES`: present = full day no fines, half, absent, leave = paid leave not deducted, off = paid off) and keeps `corrected: {status, note, was}`; adjustments (`kind` earning|deduction) give `extra_earnings`/`extra_deductions` added to net, shown on slips (one row each), the export (Adjustments sheet, extra columns) and the Salary table. `paid_on`, `leave_days`, `corrections` per employee; `totals.paid_count/paid_amount`.
- **Undo**: `snapshot()`/`undoable()` copy the files a change touches (settings, meta, month) into an in-memory stack (20) before PUT settings, month edits, uploads, lock/unlock, delete month, staff import; failed changes drop their snapshot. `POST /api/undo`. Cleared on data-folder change and restore. The UI shows Undo in the toast after a change.
- **Staff**: `left_on` date. The Staff page is a read-only list (company/shift pills, salary with "default" tag, bank status) with status cards that act as view filters (`staffView`: active / no_salary / no_bank / no_company / left / all); editing happens in the employee side panel (`openStaff`, `#staff-drawer`, also used as the profile from the Salary page and Reports — `openProfile` = `openStaff`). Opening from a "missing" view focuses that field; ↑/↓ step through the list (`staffRows`, `drawerIdx` keeps the place when a fix drops the person out of the view). Bulk company/shift bar floats at the bottom only while rows are ticked. `GET /api/staff.xlsx` + `POST /api/staff/import` (`lib/staffio.js`; rows matched by Staff ID, blank clears, company/shift by name, each row applied separately with `applyPatch`, reply `{added, updated, unchanged, errors}`). `GET /api/staff/:id/profile` (history across months + advances).
- **Printing**: `GET /api/staff/:id/slip.pdf?inline=1` opens in the browser; `GET /api/slips.pdf[?company=]` = all slips in one PDF (`buildSlipsPdf`).
- **Reports**: `GET /api/reports` (`lib/reports.js`): per-month totals + net per company, people totals for the open month and all months.
- **Backups** now contain `data/settings.json`, `data/meta.json`, `data/months/*.json` (+ legacy `current_upload.json`); `POST /api/backup/restore {name}` makes a safety backup, validates every file, then replaces the data files (config.json is not restored).
- **PIN lock** (`lib/auth.js`): `config.pin = {salt, hash}` (scrypt). With a PIN every `/api` call except `/api/auth*`, `/api/version`, `/api/update` needs the `staffpay_session` cookie (HttpOnly, SameSite=Strict; expires after 30 min idle or restart). 5 wrong PINs → 30 s block (also for PIN change). `GET /api/auth`, `POST /api/auth/unlock|lock`, `PUT /api/auth/pin {current, pin}` ('' removes; changing needs an unlocked session). Forgotten PIN: delete `pin` from config.json.
- UI (`public/app.js`): Salary page month bar (switch / lock / delete), setup checklist, search + sortable headers (`salarySort`), Paid + Adjust. columns, clickable day tiles → correction dialog (`openDayFix`), adjustments form in the expanded row (`.detail-inner` is sticky to the visible width), employee panel (`openProfile`), Reports page, Settings Security card + Restore buttons, lock screen. Generic dialog: `openModal(html, {wide})` / `closeModal`. Static files are served `Cache-Control: no-cache`.
- Don't run `npm run dev` against real data while editing server code: `node --watch` restarts on every save and runs migrations on `data/`.

## Salary rules

`settings.rules` are the default rules; a company with `rules` uses its own full set instead (normalized from the defaults). `calculatePayroll` picks `employee.rules` per employee (`rules_name` = company or 'Default'); slips and exports must read `e.rules`, not `report.rules`. The Salary rules page edits one scope at a time (`rulesScope`, picked with the Default/company tabs).

Attendance classification was validated against the user's `Sample_Attendance_Salary_Output_Sep_2026.xlsx`. The salary basis was later changed at the user's request (so totals no longer match that sample):
- Salary is entered **monthly** only. Base = the monthly salary (or `rules.monthly_salary` when blank) regardless of month length. Daily rate = monthly ÷ `rules.salary_divisor` (30.5); deductions at that rate are rounded to the rupee.
- **Every absence is deducted** at the daily rate (`allowed_absences` = 0 since v3; was 2). Half day deducts `half_day_deduction` (0.5) day.
- **Missing punch = leave** (`rules.missing_punch_as_leave` = 1): a day with only a clock in or only a clock out (after the single-punch move below) is Absent (deducted, no fines; `missing_in/out` kept for display). With the flag at 0 it is Present with the missing-punch fine (old behaviour).
- **Overtime incentive** (`rules.overtime_pay`, `overtime_min_minutes` 60, `overtime_block_minutes` 30): on a full workday with both punches, extra = clock out − the day's logout (shift logout; Sunday `sunday_logout_time`; clock out after midnight handled). Nothing below the minimum; otherwise `ot_minutes` = extra rounded down to whole blocks (20:00 logout: 20:59 → 0, 21:10 → 1 h, 21:35 → 1.5 h). Early arrival doesn't count. Paid per hour at `overtime_mode`: `'hourly'` = the employee's hourly rate, `'fixed'` = `overtime_fixed_rate` ₹/h for everyone (`overtime_rate` on the employee holds the rate used). On the Salary rules page, `data-show="a=1&amp;b=x"` hides an input unless every condition holds (checkboxes read 1/0) — all overtime inputs depend on `overtime_pay=1`. Hourly rate = daily rate ÷ shift hours (login→logout); incentive = total OT hours × hourly, rounded to the rupee, added to net.
- **Every day is a working day** (`rules.weekends_working` = 1): the device marks every weekend day `WO`/`WOP` (and holidays `H`), so those are re-classified by punches — punches → workday (late/missing apply), no punches → absent. With the flag at 0 they are paid offs with no fines.
- **Sunday is a short day** ending `rules.sunday_logout_time` (15:00; time after it is overtime): a device Half Day on Sunday with Clock Out at/after that time (− grace) counts as a full day.
- **Single punches** (`readPunches`): the device fills Clock In first, so a lone evening punch arrives as Clock In. A lone Clock In at/after the shift midpoint (login→logout; Sunday login→`sunday_logout_time`) is moved to Clock Out (`moved: 1`). With `missing_punch_as_leave` off, a day with a clock-out but no clock-in is **Present** with a missing-punch fine and never late — even when the device marked it Absent. Late is judged only from a real Clock In.
- **Advances** (`advanceForMonth`, `advanceSchedule` for the full month-by-month plan shown on the Advances page): from `start_month` each month recovers `installment` (or that month's override, e.g. 0 to skip) capped at the remaining balance, until repaid; the schedule is recomputed from the start each time, so overrides push later months. The sheet month's recovery is deducted after fines (`advance_deduction`).
- **Late arrival** (`rules.late_mode`): `'fine'` = `late_fine` per late day; `'hourly'` = late minutes measured from shift login (late itself still needs > login + grace), rounded up to `late_hour_block` (60: 9:15 for 9:00 = 1 h), deducted at the hourly rate. Both land in `late_fine` (₹) so totals/fines need no special case; `late_hours` holds the hours.
- Late / missing-punch fines never apply on Absent days (no punches or missing punch) or paid holidays. Tests for the pre-v3 behaviour pass `OLD` rules explicitly.
- UI colours: missing punch = orange (`c-missing`, takes priority over late), late = yellow, absent = red.
